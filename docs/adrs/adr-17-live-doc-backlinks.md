# ADR-17 — live-doc backlinks in code

## CONTEXT

> Every governed code file carries one block of wikilinks naming the ADRs and docs it answers to. The block holds links and nothing else; the linker writes it.

## ASSERTIONS

1. Every code file the manifest matches carries exactly one live-doc block ([[GLOSSARY]]) — a `LIVE-DOC:START` … `LIVE-DOC:END` region in that file's native comment syntax, at the top of the file. A matched file with none, or with two, is a defect.
2. The block holds wikilinks only: the ADRs governing the file and the docs those ADRs own. No prose, no restatement of a rule, no explanation — a block that paraphrases a doc offends exactly as an ADR that inlines a fact does ([[adr-00-discipline]] rule 1).
3. The file → links mapping is owned by the linker manifest. Widening or narrowing a file's governance is an edit to the manifest followed by a re-run; a hand-edited block that disagrees with the manifest is drift, corrected by re-running.
4. `models.py`, `views.py`, `viewsets.py`, `serializers.py`, `urls.py` and the permission classes additionally cite [[API]] — the one doc beyond the ADRs that the route surface answers to ([[adr-51-api-and-backend]]). No other file type cites it.
5. `docs/CODEMAP.md` is generated by the linker from the blocks and is never hand-kept. The block is the record of a file's governance; CODEMAP is its inverse index.
6. The block grants no authority and duplicates no rule. Where a block and a doc could be read to disagree, the doc wins. Wikilinks in code produce no Obsidian backlink — CODEMAP is the graph, and the block is a greppable pointer for whoever opens the file.
7. The linker is the sanctioned path, vendored per [[adr-02-harness]] and listed in [[SKILL-INVENTORY]]. Blocks are applied and checked by running it, never authored by hand; its manifest and script are tooling, not doctrine.

## FORBIDDEN

- **NEVER** hand-author or hand-edit a live-doc block (rules 3, 7). The manifest is the mapping and the linker is the writer; an edited block is drift that the next run silently erases.
- **NEVER** put prose in a block (rule 2). It is links only, because a block that explains a rule becomes a second copy of it.
- **NEVER** edit `docs/CODEMAP.md` by hand (rule 5). It is output; the blocks are the input.
- **NEVER** cite [[API]] from a file type outside rule 4's list. The route surface answers to it; nothing else does.

## REJECTED

- **A prose header instead of links** — a short paragraph at the top of each file explaining the rules that govern it. Rejected because it puts a copy of every rule in every file, and the copies drift the moment a doc changes. The block names the doc so the reader arrives at the current text.
- **Hand-maintaining the doc→code direction** — writing CODEMAP by hand alongside the blocks. It lost immediately: two hand-kept directions disagree, so rule 5 generates one from the other.
